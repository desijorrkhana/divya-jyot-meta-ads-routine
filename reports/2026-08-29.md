## ⚙️ INFRASTRUCTURE FIX THIS RUN — read this before trusting speed-to-lead below
`sheet.contact_history` (the tool that gives minute/hour-level contact lag instead of day-level)
has returned **100% null brackets for every lead, every run, for 4 straight days (26–29 Aug)** —
previously blamed on thinning Drive revision coverage. Root cause found and fixed this run: the
xlsx-revision parser (`_parse_fb_tab_xlsx` in `fetch_all.py`) read the phone number from a
**hardcoded column index (5)** — but a blank spacer column in the live sheet sits at that
position, with Phone actually one column over (index 6). Every phone lookup against a raw
revision export was silently matching nothing, so no lead's row/feedback state ever registered
as "present" — hence permanently null brackets, for every lead, regardless of how fast the team
actually worked them. **Fixed to resolve Phone/Feedback columns from the header row on every
call instead of a fixed index** (the same defensive pattern already used elsewhere in this
codebase), and verified against a live revision export before and after. Re-ran `fetch_all.py`
with the fix: brackets are populated again (see Section 4) — confirmed this was a code bug, not
a Drive quota or sheet-structure problem. **This means the last 4 days of reports understated
contact precision as "day-level only" when finer data was silently available but broken** — no
retroactive correction needed (nothing was reported as SLOWER than reality), but flagging for
the record. Fix committed; see LEARNED RULES.
